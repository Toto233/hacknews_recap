## 1. Claude 发现具有 CRISPR 样重复序列的噬菌体酶系统 (Claude discovers a novel enzyme system with CRISPR-like repeats)





Anthropic 新成立的生命科学团队披露一项早期研究：研究人员让约 950 个 Claude 智能体在 21 小时内搜索 DNA 数据，分析超过 20 万种逆转录酶，筛出约 3500 个候选系统，最终聚焦于一种主要见于噬菌体的组合。它包含此前已被发现的逆转录酶、一个功能未知的邻近蛋白，以及一串间隔规则的非编码 DNA 重复序列。Claude 首先注意到后两者与该酶共同出现；团队把这种组合称为“阵列相关逆转录酶”（ART）。初步实验显示，这组重复序列也会表达为不同的短 RNA，因此在结构上令人联想到 CRISPR。但 ART 的实际生物学功能尚不清楚，更不能据此说它已成为基因编辑工具。Anthropic 称，智能体负责数据库搜索和候选分析，人类科学家负责实验验证；团队已发布预印本，并将继续研究其作用机制。

原文链接：https://www.anthropic.com/news/claude-discovers-novel-enzyme-system

论坛讨论链接：https://news.ycombinator.com/item?id=49820134

HN 讨论主要在厘清“发现”的边界。一位评论者认为，更准确的说法是 Claude 识别出一种已知逆转录酶周围尚未描述的基因组排列，而非从零发现了酶；治疗应用的主要难点也未必是找到新核酸酶。另一位使用 Claude Science 的研究者称，它善于辨认 DNA 邻域中的模式，却必须由人复核并留下可追溯的分析记录。跟帖有人担心模型搜索结果难以复现；该研究者回应，模型的判断可以作为线索，但后续仍应独立重现分析和实验。这些评论既肯定数据挖掘潜力，也警惕把早期线索宣传为成熟技术。

## 2. 25 行 Python 模仿 Jev：本地模型也能输出分类概率 (Jev in 25 Lines of Python)



NobodyWho 发布了一篇明确标为戏仿的技术短文，用约 25 行 Python 演示“给定选项并输出概率”的分类流程。示例下载 Qwen3-0.6B 的 GGUF 模型，通过 llama-cpp-python 在本地运行：提示词要求判断一封索取非公司登录页密码的邮件是正常、垃圾邮件还是钓鱼邮件；程序读取三个选项字母的下一 token 分数，再用 NumPy 归一化成概率，示例里“钓鱼邮件”为 0.885。作者意在说明这种表面能力可以用很少代码复现，并强调无需调用远程 API、无需合成数据或强化学习训练。不过文章也承认，这并不等同于 Jev 所称的决策模型或经过校准的概率，结果并非总正确；文末还列出更完整的开放实现。因而它是对产品叙事的技术反讽，不是一份证明两者性能相同的评测。

原文链接：https://www.nobodywho.ai/posts/jev-in-25-lines/

论坛讨论链接：https://news.ycombinator.com/item?id=49812769

HN 评论聚焦概率数字到底是否可靠。sigmoid10 指出，聊天模型本来受训生成自然语言，直接读取“A、B、C”的下一 token 概率，可能把模型想写的完整回答误当成分类倾向；他建议用结构化输出表达预定义类别。dTal 反驳，若只让模型自己口述信心值，数字更可能是编造的；读取 token 概率有用，但应先检查选项合计占输出分布的绝大部分，再轮换选项与字母的对应关系以抵消位置偏差，并留意分词方式。两人的分歧不是能否分类，而是这种数值应如何约束、校验和解释。

## 3. 意大利通过重启核能法律框架，尚未批准建反应堆 (Italian parliament votes for return to nuclear energy)


据 ABC News 刊载的美联社同篇稿件，意大利参议院以 81 票赞成、51 票反对、7 票弃权，最终通过为恢复核能发展建立法律框架的法案；众议院此前已通过。法案授权政府在未来 12 个月制定反应堆许可、安全标准、核废料处理及选址等实施细则，但并未批准兴建任何一座反应堆，真正动工仍需多年。梅洛尼政府把增长的电力需求、减碳和能源安全作为理由，重点考虑小型模块化反应堆等先进技术。意大利曾运营四座核反应堆，1987 年公投促使退出核能，2011 年公投又否决了重启计划。报道指出，该国仍缺永久核废料处置设施，未来选址可能面临地方反对；小型模块化反应堆的经济性也尚待验证。能源智库 ECCO 认为建立监管框架有价值，同时主张继续投入能效、可再生能源、储能与电网。原 AP 页面无法获取，故此条采用上述替代来源，并用 ANSA 核对参议院表决。

原文链接：https://apnews.com/article/italy-nuclear-chernobyl-4891b6b7c7791ae84db6b0bf0f7cf567

论坛讨论链接：https://news.ycombinator.com/item?id=49819221

摘录中的 HN 评论主要围绕核电全生命周期成本争论。jacquesm 质疑小型模块化反应堆方案常缺从部署、运营到退役的完整财务测算，担心补贴掩盖真实盈利能力。asmodeuslucifer 进一步声称各国核电都不盈利，但承认能源安全可能使国家愿意承担成本；这一笼统说法遭到以法国为例的跟帖反驳。另一位法国评论者则强调，新建与退役费用也应计入账本。上述都是评论者的观点，不能据此断言所有核电项目必然亏损；它们提醒读者关注法案落地后的投资与退役安排。

## 4. ReBarUEFI 让更多旧 UEFI 主板支持 Resizable BAR (ReBarUEFI: Resizable BAR for almost any UEFI system)




开源项目 ReBarUEFI 提供一个 UEFI DXE 驱动，目标是在未获厂商正式支持的系统上启用 Resizable BAR，使处理器可以映射更大范围的显卡显存。使用者需依项目 Wiki 修改固件、加入模块，再通过 ReBarState 设置 BAR 大小；运行时驱动介入 PCI 设备资源分配，让固件按所设大小分配地址空间。项目建议开启 4G Decoding、关闭 CSM；缺少 4G Decoding 时，BAR 大小可能被限制在 1GB 或更低，部分旧固件还需额外补丁。作者列出从地址空间限制到 NVRAM 白名单的修补方案，也提醒错误设置可能导致无法启动，届时需清除 CMOS。Linux 在具备 4G Decoding 的部分环境可不改 BIOS 实现类似功能；Windows 目前没有已知的免固件修改方案。项目标题的“几乎任何”因此不代表零风险或保证兼容。

原文链接：https://github.com/xCuri0/ReBarUEFI

论坛讨论链接：https://news.ycombinator.com/item?id=49781862

HN 有评论者解释，Resizable BAR 能突破传统约 256MB 的显存映射窗口，让 CPU 一次访问更大显存区域，但其声称的游戏性能提升幅度应视硬件和游戏而定。另一位评论者认为，显卡本身和 PCI 路径也需支持，且对根端口能否全由固件处理仍存疑，不能把项目理解成让任意老显卡凭空获得该能力。讨论随后转到旧主板固件改造：有人回顾为旧机器添加 NVMe 启动或新 CPU 支持的类似尝试，并认为开放固件更便于维护；另有人指出 Coreboot 可支持的主板范围有限。讨论强调兼容性与固件风险。

## 5. 社区接手旧警局后，波托贝洛钟楼重新校时 (Fixing the Portobello Police Station Clock)





苏格兰波托贝洛的旧警察局转为社区所有后，钟楼上的三面时钟无人知道如何校时。作者受朋友邀请，爬上塔楼摸索这套可能沿用十九世纪机构、后来加装电机与控制盒的设备。他们发现电机经齿轮驱动每小时转一圈的主轴，抬起齿轮上的棘爪后便能手动转轴，并借指针背面的配重推断塔外时间。整点报时更复杂：带 PIC 微控制器的控制盒通过两个开关分别感知整点和敲击次数，“advance”键要按住数秒才会推进报时小时数。下午四点，外部时针显示正确，钟也敲了四下，验证了校时方法。不过考虑到附近居民可能不喜欢钟声，众人随后断开报时电机；作者并未宣称报时功能已正式恢复。控制盒状态灯含义、电池状况及其设计者仍待后续查明。文章把一次社区建筑维修写成了实地排障记录，而不是完整的钟楼翻新报告。

原文链接：https://pointinthecloud.com/2026-04-11-211700.html

论坛讨论链接：https://news.ycombinator.com/item?id=49817469

摘录的 HN 评论主要谈后续维护。一位评论者看到通往塔楼的木梯，建议贴防滑砂纸条，认为这是低成本改善攀爬安全的办法；他还提议用 PoE 摄像头远程观察齿轮和控制盒状态灯，以免对老机构做侵入式改造。同一人根据照片推测备用电池可能是常见的 12 伏、约 7 至 8 安时密封铅酸电池，建议查不到更换记录时就检查或更换。另一位评论者对摄像头方案提出更朴素的反问：要知道钟是否仍在走、时间是否准确，直接从塔外看钟面即可。这些都是评论者的维护建议，并非现场已实施的改造。

## 6. 谷歌推出 Gemini 3.8 文本转语音：设计声音、逐句控制表演 (Gemini 3.8 text-to-speech)



谷歌发布 Gemini 3.8 Flash TTS 与 Flash-Lite TTS：前者侧重从自然语言描述生成角色声音、设计口音和表演方式，后者侧重高吞吐、较低成本的配音与语音代理。两款模型都支持逐句指定语气、节奏及双人对话等表现；谷歌还展示了长音频与笑声、叹气等提示的用法。Flash TTS 提供超过 2000 种现成声音，并称可用有权使用的 30 秒录音复刻声音。对此，谷歌要求声音本人提供与样本匹配的口头同意录音，生成音频也带 SynthID 水印；这不等于滥用风险已消除。官方称模型已开始进入 Gemini API 和 AI Studio，面向企业的 Gemini Enterprise API 则是后续推出；Flash 对应 Gemini Notebook，Flash-Lite 对应 Google Vids。AI Studio 的声音复刻还受地区限制。

原文链接：https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-8-text-to-speech/

论坛讨论链接：https://news.ycombinator.com/item?id=49817615

摘录的 HN 评论主要抱怨谷歌各产品线的上线节奏不一致：有开发者说消费者应用、AI Studio 与企业云平台可能拿到不同模型或能力，企业禁用前两者时尤其难规划。其他人以个人、教育和 Workspace 账号看到的不同模型列表补充这种体验，也有人认为大公司产品线分散并非谷歌独有。另一个讨论点是声音复刻：Simon Willison 注意到官方允许用 30 秒样本复制有权使用的声音，并推测其他服务已广泛提供类似能力，谷歌因此更愿意推出。关于内部组织和竞争位置的说法只是评论者猜测，并非官方解释。

## 7. Token 会便宜到不值得计费吗？一篇关于 AI 成本的推演 (Tokens too cheap to meter)





作者 jyn 整理模型、硬件和推理软件的效率变化，认为完成同等任务的 AI 成本正在快速下降，未来大模型可能从单独产品变成软件基础设施。文中分别讨论 GPU 能效提升、模型的价格与质量前沿、推理引擎优化，以及专家混合架构和 Mamba 混合架构对云端计算或本地内存的不同影响。专用分类模型 Jev 被用作极低价格的例子：文中转述其每十亿输入 token 42 美元、输出不另计费的标价，但也承认无法证明该价位可长期持续。作者进一步推测，便宜的模型调用可能进入原本使用常规工具的环节，并让用户多一种选择：让模型按需求生成软件；需求增加也可能抵消单次推理降价。他预计未来数年本地模型接近当下前沿水平，但这属于预测，不是已实现的性能。文章的核心是成本趋势及其可能后果，而非宣布所有 token 已经免费。

原文链接：https://jyn.dev/tokens-too-cheap-to-meter/

论坛讨论链接：https://news.ycombinator.com/item?id=49813482

摘录的 HN 评论围绕文章“模型调用会比 grep 等工具还便宜”的推演。一位评论者引用“不可无限持续的趋势终将停止”的观点，认为能效改善不能永久指数增长；高质量编译工具的单次成本更像模型成本逐渐逼近的下界，而不是必然被越过。回复者补充，如果模型能降到比现有 grep 更便宜，grep 本身也可能继续优化。另有评论者设想专用芯片可能降低两者成本，但指出为不断变化的模型固化硬件有过时风险；后续回复提醒，ripgrep 一类搜索已经常受输入输出速度限制。讨论质疑外推的边界，并未否定现有降价案例。

## 8. Claude Code 关闭遥测曾跳过 AGENTS.md，开发者称已修复 (Claude Code reads AGENTS.md only when telemetry is on [fixed])


Claude Code 2.1.277 宣布支持 AGENTS.md：项目没有 CLAUDE.md 时，改读前者作为项目指令。但博主 Przemek 实测发现，在 2.1.280 中，负责读取该文件的内置 agents-md 插件受远程功能开关控制；关闭遥测或非必要网络流量后，开关无法取得启用值，程序便默默跳过本地文件。作者在仅含 AGENTS.md 的空目录中写入测试词，以两轮命令行会话验证：关闭上述流量时模型答不出测试词，清除两个环境变量后才可读取；把变量设成 0 或只在项目设置里覆盖均无效。他的临时办法是在同目录创建仅含“@AGENTS.md”的 CLAUDE.md，利用已有导入机制加载指令。作者认为本地文件读取不应依赖遥测，至少应在跳过时明确提醒用户；文中也提到全局 AGENTS.md 和共享技能目录尚未获得同等原生支持。

原文链接：https://blog.szypowi.cz/p/claude-code-reads-agents.md-only-when-telemetry-is-on/

论坛讨论链接：https://news.ycombinator.com/item?id=49814947

HN 标题的“[fixed]”指后续修复，并非博主复现有误。一位 Claude Code 开发者解释：AGENTS.md 由新的 Mods 扩展机制实现，为推出时保留远程关闭开关；关闭遥测使客户端取不到功能开关，是上线设计失误。他道歉并称已在当日发布的 2.1.281 修复。对此，评论者有分歧：有人认为渐进发布需要紧急停用能力，也有人认为隐形停用违反已公布的功能预期。另有用户提醒，项目同时存在 CLAUDE.md 时默认仍优先读取它，不能把所有 AGENTS.md 未生效都归因于遥测。

## 9. 事故复盘别止于解释：领导更想知道下次会改变什么 (I don't want the details)



Michael Heap 回忆，一次并不灾难性但需要向工程高级主管说明的工作失误发生后，他刚准备解释经过，主管便打断说“不想听细节”，只想知道将改变什么。作者起初觉得这很轻慢，后来理解为对团队能力和善意的默认信任：如果每一步决策都能解释得合情合理，组织很容易因同情而放弃改变，半年后同类问题重演。他主张复盘从“为什么发生”进一步转向“怎样让同类失败下次更不可能发生”。例如人员休假导致归属不明，就明确缺席时的责任交接；需求临近上线变化，就规定发布窗口内的决策方式；低价值告警淹没值班者，就改善信噪比。仅写“以后更小心”或“加强沟通”，仍依赖人的记忆，不算可靠措施。不过他也警告，不是每次失误都值得新流程；如果预防成本高于偶发损失，应明确接受风险，而非假装已经解决。

原文链接：https://michaelheap.com/i-dont-want-the-details/

论坛讨论链接：https://news.ycombinator.com/item?id=49815466

HN 评论集中质疑“不想听细节”的边界。一名评论者认为，领导若不知道发生了什么，就无法判断后续措施是否合适；只问下一步可能强化管理层脱离一线的倾向。他也指出，自己见过的优秀领导同时了解底层情况与整体方向。回应者则认为，询问改进并不等于不信任，而是为了了解团队计划、配置资源并清除障碍。另一位评论者进一步区分设定结果期望与亲自规定解决办法：领导未必需要重审每个技术细节，但仍须推动团队达成可检验的改变。争论并非是否要复盘，而是管理者应掌握多少事实，才能既承担责任又不陷入微观管理。

## 10. Waymo 推出公交接驳奖励：两小时内换乘返 2.85 美元 (Transit rewards)





Waymo 宣布在旧金山湾区推出“公交接驳奖励”，先向员工开放，再于未来几周逐步扩至公众，其他城市则是后续计划。乘客须在 Waymo 应用绑定 Visa 卡，并用该卡分别支付湾区的 Waymo 行程与公共交通；两段出行时间相隔不超过两小时，就会自动获得 2.85 美元 Waymo Cash，相当于旧金山一趟公交票价。这是未来乘坐 Waymo 的抵用额度，并非直接退还现金。Waymo 将自动驾驶叫车定位为轨道与公交的接驳工具，称旧金山、洛杉矶和凤凰城成熟服务区中，超过一半乘客也使用公共交通。公司同时与 Caltrain 合作，租用其车站 40 个专用停车位供车辆待命，希望缩短站点接驳等待；未来还计划把奖励和合作扩展到其他交通机构及城市。上述覆盖范围和效果是公司提出的计划与描述，并非已完成的全域推广。

原文链接：https://waymo.com/blog/2026/09/transit-rewards/

论坛讨论链接：https://news.ycombinator.com/item?id=49811065

HN 讨论很快从折扣转向湾区公共交通的结构性问题。有人以连接 Van Ness 与 Caltrain 的 47 路公交自 2020 年停运、铁路延伸项目缺少资金为例，认为奖励虽能改善现有接驳，却不能替代长期线路和基础设施投入。也有人反驳“湾区公共交通普遍不可靠”的概括，称服务在部分地区相当好，主要问题是覆盖不均。另一支讨论聚焦多家交通机构并存：有人质疑机构数量太多，也有人认为各地税收和服务范围不同，且统一票务已降低乘客感受到的分割。还有评论者强调，清洁、安全与可靠性比补贴更能决定是否转乘公交。
