## 1. 48 个 AI 代理从激光雷达图识别出玛雅遗址，论文早有记录 (My AI agents found an unmapped Maya site?)



Pietro Miotti 用 48 个 AI 代理检查墨西哥林区约 1,200 平方公里的公开激光雷达图，标出一处疑似玛雅遗址。激光脉冲可以穿过树冠缝隙，部分回波来自地面，因此能绘出卫星照片上被树木盖住的地形。代理逐张查看这种地形图，寻找平台、广场等规则形状，再查看原始测量点，判断这些轮廓来自地面还是树冠。

Miotti 把山顶一处带有平整广场和疑似金字塔的地点报告给墨西哥国家人类学与历史研究所。按他公开的回函，该机构当时在登记册里没有查到这个地点。从开始尝试到收到回复用了不到 72 小时。11 月 11 日，Miotti 更新文章，确认考古学家已在 2025 年的论文中绘出同一遗址，代理检索文献时漏掉了这篇研究。这次实验重找到了已经记录的地形，文章对遗址年代和建筑用途的推测仍需考古证据支持。

原文链接：https://pietromiotti.com/latest/maya-site

论坛讨论链接：https://news.ycombinator.com/item?id=50452455

HN 上有读者贴出此前的考古研究，另一位指出论文第 13 至 14 页展示了相关结构，Miotti 随后在讨论中确认代理漏检了论文。做过英国激光雷达地图的读者说，业余爱好者早已用公开的地形图找到过多处遗迹。他认为，这个案例也受益于激光雷达数据覆盖扩大，尤其是林地和刚公开的测绘区。另一些读者把问题转向保护：如果成批标出候选地点，考古人员未必来得及核查，公开位置也可能引来盗掘。有人回应，盗掘者同样能用公开数据，完全搁置也未必能保护地点。

## 2. AWS 推出官方本地模拟器，开发和测试可直接调用本机 API (AWS emulator)


AWS 发布了用于本地开发和自动化测试的 AWS Emulator。开发者可以把平常用的 AWS 命令行或 SDK 指向本机的 HTTPS 接口，再用模拟器生成的凭据发送请求。例如，程序可以在本地建一张 DynamoDB 表并测试读写，无需注册 AWS 账户或创建云资源。各实例分别保存自己的凭据和内存状态，退出后模拟资源随之清除，适合并行跑相互隔离的测试。Linux 可装预编译软件包，Windows 和 macOS 可通过容器运行，Rust 测试还可把模拟器嵌入测试进程。接口定义取自 AWS 发布的 API 模型，具体行为逐版本补齐和验证，未实现的操作返回 501。各版本附有与云端行为对照的报告。源码主要采用 CC0 1.0 公共领域奉献，仓库 vendor 目录的代码采用 Apache 2.0 许可证。

原文链接：https://github.com/aws/aws-emulator

论坛讨论链接：https://news.ycombinator.com/item?id=50456631

HN 的讨论集中在本地测试能覆盖多少部署问题。有人希望把整套基础设施部署指向模拟器，重现资源创建顺序出错时难排查的超时，也有读者希望每个测试结束后能快速重置状态。有人援引 AWS 的安全文档，指出本机使用模拟器自己签发的密钥时不会被权限规则拒绝，桶策略等也有缺口，权限验证仍需在真实云环境进行。还有人担心这只是一次用 AI 编写大型项目的演示，一位回复者表示团队计划维护这个产品，并贴出亚马逊的官方发布说明。

## 3. 《Python 之禅》作者、Timsort 发明者 Tim Peters 逝世 (Tim Peters has died)



Python 创始人 Guido van Rossum 11 月 11 日在 Python 官方论坛宣布，早期核心贡献者 Tim Peters 已于 7 月 15 日逝世。Peters 在 Python 发布不久便参与设计，曾说服 Guido 支持整数和浮点数直接混合运算，因为这更符合用户直觉。2002 年，他为 Python 列表设计了 Timsort。它会找出输入中已经有序的连续片段，再利用这些片段完成排序，后来也被 Java 和 Android 采用。他写下的《Python 之禅》收录为 PEP 20，概括了清晰、可读等设计偏好，在解释器中输入 import this 就能看到。Guido 还回忆，Peters 常在邮件列表耐心讲解技术细节，解释设计取舍。老同事 Chris McDonough 则提到，Peters 曾于 2001 至 2014 年担任 Python 软件基金会董事。

原文链接：https://discuss.python.org/t/in-memoriam-tim-peters-1952-2026/110028

论坛讨论链接：https://news.ycombinator.com/item?id=50450488

HN 上有人重贴了 import this 的输出，也有人回忆 Peters 如何把复杂问题讲清楚。一位读者在九十年代解析文件时发现两种写法速度差很多，Peters 帮他找到原因。字段多半是空格，先检查空格就能省掉许多整数解析。一位常读 Python 开发邮件的人想起他为《Python Cookbook》第二版撰稿，说他能把技术细节讲得深入又好读。还有人提到他参与制作垃圾邮件过滤工具 SpamBayes，合作者 Gary Robinson 随后现身，指认了 Peters 当时写的一段代码。

## 4. 烟雾误报关掉机房空调，Jane Street 工程师赶回拔电源 (A false smoke alarm almost drowned Jane Street's only NYC datacenter)




前 Jane Street 系统工程师 Michael Bacarella 回忆，纽约机房隔壁的准备间施工扬尘，触发了烟雾警报。警报按设计关掉机房空调，也让平时没有水的喷淋管道充水加压。喷头还要等周围温度达到阈值才会打开。那晚真正推高温度的是仍在运行的服务器。香港团队有人看到多台机器温度接连上涨，打电话给住得近的 Bacarella。他赶回办公楼 33 层，逐排拔掉设备电源，读数最后停在 143.6 华氏度（62 摄氏度），低于他所说约 150 华氏度的危险线。纽约主要市场当时已收盘，机房次日恢复。团队决定保留喷淋，加强流程和监控。Bacarella 随后用 OCaml 写了一个程序，每分钟读取各站点 Linux 服务器的温度、计算平均值，在多台机器一齐变热时及时通知系统团队。

原文链接：https://michael.bacarella.com/2026/11/10/false-smoke-alarm-jane-street-datacenter/

论坛讨论链接：https://news.ycombinator.com/item?id=50455394

HN 读者关心哪些措施能免去逐台拔线。一位读者提出在机房设置能切断设备电源的实体紧急按钮，并考虑与烟警联动。另一位提醒，断电能避免带电设备遇水，却挡不住喷淋后的清理和停机。也有人分享自己参与设计的机房会在烟警响起后维持室内空调，因为设备只循环同一间房的空气。回复则提醒，气流也可能延迟喷头动作，方案要看现场配置。还有人问为何采用喷水，Bacarella 说他们建的其他机房用过气体灭火，但他记不清这间保留喷淋的理由。

## 5. 研究者解锁一张 8 GB 英伟达矿卡的 80 GB 显存 (Using voltage glitching to unleash the A100 in my mining card)



英伟达的 CMP 170HX 矿卡和数据中心显卡 A100 共用 GA100 芯片。硬件研究者 Kate 测试了前者。标称 8 GB 的矿卡在出厂时只向应用开放部分显存，但作者检查的十张卡中有九张拥有完整可用的 80 GB 显存，另一张只能用到 64 GB。

英伟达用芯片里的电子熔丝区分产品功能并屏蔽有缺陷的单元。作者用短暂的供电扰动触发控制器异常，改写了限制配置，再配合修改过的驱动让应用用到更多显存。实测卡通过了全显存读写和 vLLM 推理测试。在 OpenCL 的半精度乘加测试中，改过的矿卡跑到约 85.86 TFLOP/s，零售 A100 的对照成绩约为 72.49 TFLOP/s，相差约 18%。不同卡能开启的计算单元数量取决于芯片状态。作者说，发表前已将发现告知英伟达产品安全团队。

原文链接：https://blog.kate.land/posts/using-voltage-glitching-to-unlock-the-a100/

论坛讨论链接：https://news.ycombinator.com/item?id=50451903

读者最关心的是，单卡实验能不能在一批旧矿卡上重现。有人想组本地 AI 算力机，追问二手价、可用显存和计算单元的差异会不会抵消成本优势。有人回复，过去已有软件方式能把部分 8 GB 卡扩到 64 GB，但接口带宽仍有限。另一位读者怀疑，某些功能可能是因为出厂检测发现缺陷才被关掉。回复指向作者的实测，指出有些单元确实被单独标记为有缺陷，解除产品限制时仍需保留对这些单元的屏蔽。另有人质疑 10 GB 型号曾被传出的 80 GB 结果可能是地址映射重复。

## 6. 苹果旗下 Claris 开放 Harbor 预览登记，可让多台 Mac 一起跑本地 AI (Apple has new Mac app coming to make running local AI models easy)





苹果旗下的 Claris 为 Mac 上的 AI 工具 Harbor 开设了私有预览登记页。Claris 将它定位为在搭载苹果芯片的 Mac 上运行开放权重模型的服务端，计算在用户设备上完成。根据公司说明，单台 Mac 可以先提供一个供应用调用的接口。要运行单机内存装不下的模型，可以用 Thunderbolt 5 连接多台兼容 Mac，让这些机器的统一内存共同承载模型。

9to5Mac 援引 Aaron Perris 找到的产品材料称，Harbor 拟在应用内提供模型浏览、下载和载入功能，也可自动发现已连接的 Mac。这样一来，用户可以从界面管理模型和机器，减少部署服务时的手动配置。Perris 随后称原先看到的 App Store 页面已经下架。Claris 的登记页目前提供后续消息订阅，公开发行日期、定价和详细机型要求仍待公布。

原文链接：https://9to5mac.com/2026/11/10/apple-has-new-mac-app-coming-to-make-running-local-ai-models-easy/

论坛讨论链接：https://news.ycombinator.com/item?id=50446520

HN 读者主要在比较本地运行和云端服务的实际成本。一位用户分享了在 Mac 上用本地模型长时间审查代码的经验，认为按调用量计费的任务可能值得迁回本地，也提到机器会遇到散热限制，速度和效果有差距。回复质疑其云端费用估算，并指出还要考虑用电、硬件故障和维护。另一些读者已经用过 Ollama、LM Studio 或 llama.app，希望看到厂商维护的工具。有读者把多台 Mac 能共同提供内存视为 Harbor 最值得关注的能力，因为它关系到单台机器能否容纳模型。

## 7. 美联航限制未经授权的第三方 AI 助手代订机票 (United Airlines bans AI agents from booking flights on behalf of travelers)



美国联合航空在 11 月 11 日宣布，将限制未经美联航授权的第三方个人 AI 助手访问其订票系统。措施覆盖美联航网站和应用，也延伸到旅行社与订票聚合平台。公司正在更新预订、出票和分销政策。CBS 援引航空业分析人士称，旅客仍可通过现有的航班比价平台查找美联航票价。

美联航列出的顾虑集中在助手能代办哪些操作。把账号凭据交给第三方工具可能暴露敏感信息，助手也可能买下旅客没打算购买的机票、修改账号或动用 MileagePlus 里程。办理值机还有额外要求，例如旅客本人需要确认行李内没有违禁物品。航空业分析师 Henry Harteveldt 另向 CBS 提出商业层面的解释。他认为航空公司也希望掌握订票流程，避免增加一个影响力可能更大的中间商，并减少自动查询带来的开销。

原文链接：https://www.cbsnews.com/news/united-airlines-bans-ai-agents-booking-flights/

论坛讨论链接：https://news.ycombinator.com/item?id=50458900

HN 读者争论，机票预订究竟有多少步骤值得交给助手。有读者说，固定日期的简单往返用比价网站很快，选座、转机和大额付款仍想亲自决定。有人回帖说，日期和机场有多个选项时，反复筛组合才是最费时间的部分。另有读者列举美联航结账时反复跳转的页面，从升舱、选座到信用卡广告，认为助手可以代劳。另一串讨论追问，能像人一样操作浏览器的助手如何识别。回复指出，即使系统当时识别不出，航空公司也会担心买错票之后的退款请求和客服争议。

## 8. 用 WebGL2 把沙子倒进浏览器，倾斜手机就会流动 (Hyper-Realistic Sand with WebGL2)


Safe Sand 是一个用 WebGL2 和 JavaScript 制作的网页沙盘。点一下倒沙按钮，再倾斜手机，沙粒就会沿屏幕滑落。快速晃动手机会把沙甩散，也可以用手指推开沙堆，在上面画出沟槽。电脑端能用鼠标推沙，用方向键模拟倾斜。倒沙前可以挑河沙、海滩沙、沙漠沙等材质，也能选择沙子下面的底图。

作者在项目文档里介绍，GPU 会按设备性能模拟约 10 万至 46 万颗沙粒，每颗都有自己的尺寸、颜色和摩擦力。程序每帧根据颗粒位置重建沙堆高度，用坡度计算沙粒如何往下滑，同时渲染遮挡和阴影。沙堆要倾斜到一定角度才会散开，声音也随沙粒活动量变化，由许多细小的撞击声合成。遇到持续掉帧时，程序会先检查浏览器是否限制了帧率，再决定要不要降低渲染分辨率或减少沙粒。

原文链接：https://av.github.io/safe-sand/

论坛讨论链接：https://news.ycombinator.com/item?id=50453288

HN 的反馈集中在沙堆看起来像不像真的，以及不同设备能否流畅运行。有人注意到石头周围有一圈水，沙堆积到一定高度也会自然塌下。另有读者比较了几种材质，觉得红色沙漠沙比海滩沙更容易结团。不过，一位读者看到部分沙粒卡住、石头滑动时不转，另一位则提到挤压后有明显回弹，都会打破真实感。

运行表现也随设备而异。一位用 iPhone 15 Pro 的读者估计只有每秒 10 帧，另有人说自己那部 2021 年的入门 Android 手机跑得像幻灯片。还有读者觉得倒沙时的声音太响，希望第一次打开时静音。

## 9. 线性规划让 Qwen 少陷入重复，改动权重约为 Astra 方案的八分之一 (Can a Linear Program Do Weight-Space Programming?)


Nathan Barry 用线性规划复现了一项模型权重编辑实验。Qwen3.5-0.8B 解数学题时容易反复输出同一段推理，直到达到长度上限。此前 GPT-6 Astra 比较了正常推理和重复时的内部状态，找出一个与循环相关的方向，再试着改动两层权重来抵消它。Barry 沿用这两层，把循环时应抑制多少、正常推理时最多能受多大影响写成约束，让求解器选出要修改的位置和幅度。

在 Barry 留出的测试集上，沿用 Astra 找到的方向，线性规划改了约 1.6 万个权重，Astra 方案改了约 13 万个，两者在 MATH-500 上分别得到 51.7% 和 50.9%。定制 GPU 求解器每次约用一分钟，这只计入求解步骤。Barry 也试了用重复检测自行估计循环方向，成绩为 47.8%。实验只针对这个模型的重复问题，自动选择要编辑的层仍是待解决的问题。

原文链接：https://nathan.rs/posts/weight-space-lp/

论坛讨论链接：https://news.ycombinator.com/item?id=50452655

HN 上有人建议把线性规划求解器交给 Astra 使用。原任务只要求通过改权重提升数学成绩，Astra 得先找到重复循环这个故障，再找出可干预的层和方向。确定想压制和保留哪些行为后，求解器可以更快算出改动方案。另一位读者认为，也可以在训练时加入约束，让模型少出现这种行为。回复指出，训练完成后仍可针对特定方向做调整。

还有读者质疑「编辑权重」这个说法容易让人以为模型知道每个参数的含义。他指出，权重之间的关系远比文件里的一个比特复杂，一项测试受益时，另一项测试仍可能退步。

## 10. Google 推出 Gemini Decisions API，可对同一份多媒体资料批量判断 (Gemini Decisions API)



Google 在 Gemini API 中推出 Decisions API，使用专门做选项判断的 Gemini Decision 1。开发者可以提交一份由文字、图片、音频、视频或 PDF 组成的输入，上限为 256K 个词元，并附上最多 1000 道彼此独立的问题。接口支持是非题、多项选择和按有序等级打分。例如，可以用同一段电话录音判断来电原因，再给处理优先级打分。模型一次计算就能给出选项概率和置信度，应用可以据此把把握不足的个案转给人工复核。

Google 公布的端到端延迟中位数约为 150 至 250 毫秒，测试条件为输入最多 16K 个词元、单次请求 1 至 100 题。定价为每百万输入词元 0.10 美元，输出词元费用为零。共同输入在每次请求中只计费一次，各题另计指令与判定条件。发布时可在 Google AI Studio 领取 API 密钥，也有用于原型开发的免费额度。

HN 有读者认为，对比小幅跑分差距，更值得留意的是能直接针对录音、视频或 PDF 做判断，因为纯文字分类已有更快或更便宜的选择。也有人问，通用语言模型原本就能按指定格式给出选项，为何还需要专门接口。另一条讨论把重点放在概率上。分数能否作为业务阈值，取决于相近置信度的答案实际上有多常正确。

有人建议换几种问法，看模型结果是否一致。回复提醒，同一套问法都得出相近分数，也可能只是稳定地高估把握。要判断分数是否可信，仍需要拿已知结果的样本核对。
