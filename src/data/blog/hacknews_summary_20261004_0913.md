## 1. Newgrounds：游戏、动画与艺术的创作者社区 (Newgrounds.com – A community of games, music, and art)


Newgrounds 今日登上 Hacker News 的链接指向网站首页，而非一篇新公告。首页按游戏、动画短片、音频、美术和漫画展示用户作品，也提供系列与合集入口；每个栏目都能看到具体作品、作者和相关论坛。网站引导访客免费注册、订阅个人动态，或以支持者身份帮助平台运营。新投稿的游戏和影片另有投票区，页面说明用户投票会影响作品能否继续留在展示队列，参与越多，投票权重也会增加。创作者资源、艺术家动态及活动日历则把发布、交流和协作放在同一站点。这里值得关注的是一个仍以个人创作为中心的综合社区，而不是 Newgrounds 当天推出了新功能、宣布了商业数据或改变了审核规则；原链接也没有提供这类消息。

原文链接：https://www.newgrounds.com/

论坛讨论链接：https://news.ycombinator.com/item?id=49940394

HN 讨论以亲历回忆为主。一名评论者讲述自己后来发现大学时玩的小游戏使用了创办人 Tom Fulp 身边的朋友作角色，并回忆他早期制作网络游戏、之后重返大学的经历；这些是个人叙述，不能当作官方站史。另一名曾在站内制作 Flash 游戏、参与论坛和 Clock Crew 的用户，回忆自己的作品及早期合作。支线争论围绕算法课程是否对开发工作有用：有人认为多数岗位依赖现成库，另有人说数据结构与算法至少曾是理解程序和求职面试的重要基础。

## 2. 特朗普将 AI 改称 SI，恶搞网站借势讽刺 (Extra Big Ass Intelligence)


这张网页借美国行政部门最近的真实改名命令玩梗。白宫 9 月 29 日签署第 14434 号行政命令，要求行政部门在官方通信、网站和非成文法文件中，用“Super Intelligence／SI”替代“Artificial Intelligence／AI”；命令仍沿用现有法定 AI 定义，没有让现有模型的能力突然升级，也没有要求社会全面禁用旧词。网站则把这一步夸张成“AI.exe 被行政命令删除”“AI 成为违禁词”，自称“纯天然 SI v1.0”。页面穿插“附近的 35B 模型”、国会用两个字母修复经济、给 AI 补贴多巴胺等假新闻卡片，以及 Brawndo 电解质广告。访客问 SI 为何能拯救经济，得到给“灵魂”定价的荒唐回答；另一条回复变成嘲讽式 429 限流提示。真实背景是政府用词政策，网页内容则是对改名、商业话术和模型万能论的戏仿，不能把笑话里的产品或政策当成事实。

原文链接：https://www.extrabigassintelligence.com/

论坛讨论链接：https://news.ycombinator.com/item?id=49941114

HN 帖主自称用 OpenCode 中的 GLM-5.3 制作网站，自己的电脑以两张 RTX 4060 Ti 运行一个改造过的 Qwen 35B 模型；他还称上线后约有 25 万次请求、曾短暂登上榜首，项目没有变现计划，预算主要是域名费。这些流量与配置是作者自述，并非独立核验。评论有人喜欢这种荒诞抗议，也有人质疑：连讽刺 AI 的文字都交给模型生成，反而让讽刺失去亲手创作的意味。另有讨论关注弱化安全限制的模型为何特别容易配合这种表演，其用途与风险应分开看。

## 3. Cloudflare 推出 OHTTP 网关封闭测试：让应用减少识别用户 (Cloudflare OHTTP gateway)





Cloudflare 宣布其托管 OHTTP Gateway 开始封闭测试，计划作为付费附加功能开放。OHTTP 把请求拆成由不同运营方掌管的中继与网关两段：中继看得到用户 IP 等标识，却无法读取加密内容；网关解密后转给应用服务器，能看到请求内容，却不应得知原始用户身份。Cloudflare 原有的 Privacy Gateway 同时更名为 OHTTP Relay；使用其新网关的客户需另找第三方中继，避免一家企业同时掌握两端信息。新服务可绑定现有 Cloudflare 域名，由平台管理加密公钥、解密与转发，普通 HTTP 请求仍可照常抵达服务器。公司称这能降低自建网关的运维和延迟负担，但目前仍是封闭测试，需登记等候，且隐私效果依赖中继与网关真正分属独立运营方。

原文链接：https://blog.cloudflare.com/announcing-cloudflare-ohttp-gateway/

论坛讨论链接：https://news.ycombinator.com/item?id=49941091

HN 讨论没有只停在产品易用性，而是集中追问信任边界。有评论者基于 Cloudflare 在网络中的广泛位置提出对数据集中化和政府获取数据的担忧；这些是质疑与推测，不能当作公司存在秘密合作的事实。另一位评论者反驳说，OHTTP 的关键恰恰是增加由第三方运营的一跳：如果 Cloudflare 只控制中继或网关之一，单方就不应同时看到用户身份和请求内容。讨论提醒读者，协议设计与实际部署必须分开看，重点核实两端是否真的独立，以及谁持有日志和密钥。

## 4. Aleph Alpha 发布德英双语开放权重模型 Kolibri (Kolibri: A Sovereign Open-Weight Model)





德国 Aleph Alpha 发布德英双语混合专家模型 Kolibri，开放权重供下载。公司称模型总参数约 780 亿、每次推理激活约 30 亿，最长支持约 100 万 token 上下文；但其常规训练最长上下文为 26.2 万 token，更长窗口需额外配置，不宜混同。它面向公共行政、工业与航空航天等受监管场景，可在本地部署以减少内部数据外传。官方介绍称，团队在德国和芬兰的基础设施上训练模型，预训练使用约 20 万亿 token，并针对德语数据、工具调用、检索增强及拒绝无依据回答作了专门优化。公司公布的多项公开和客户代理测试显示某些任务表现突出，但基准由厂商自行组织，不能概括为全面领先。权重开放也不等于训练数据或完整训练流程全部公开。

原文链接：https://aleph-alpha.com/en/blog/kolibri-has-landed-a-sovereign-open-weight-model/

论坛讨论链接：https://news.ycombinator.com/item?id=49942706

HN 评论最关注的不是单一排行榜名次，而是技术报告披露的训练细节。有读者认为它几乎像一份构建现代代理模型的教程；自称参与预训练的团队成员解释，数据清理结合精确、模糊和子串去重、启发式过滤及质量分类器。另一组评论争论“开放”的边界：有人希望训练数据来源也公开且可复现，有人指出“开放权重”本来只承诺发布训练后的参数。还有人提出德国作者作品授权与报酬的疑问。评论中对透明度的赞赏，不应被写成数据集已全部公开或版权问题已解决。

## 5. 开发者详述 Linux 在 M4 Mac mini 上启动时的“失忆”难题 (The Forgetful CPU (Linux on M4))





一名参与 Asahi Linux 生态的开发者记录了让 Linux 首次在 M4 Mac mini 上启动到命令行的过程。早期调试先受到锁定寄存器和串口输出配置的阻碍；真正影响多核心启动的是 M4 执行 ARM 的 WFI 等待中断指令后可能丢失处理器架构状态，默认行为不符合相关规范。直接按芯片型号在内核中禁用 WFI 容易误伤虚拟机：在 macOS 虚拟化环境下，该指令由管理程序截获并用于调度。最终方案转向可选择的启动参数与对 WFI/WFIT 的规避，其中防止崩溃的机制已并入 Linux 主线。作者称 M4、M4 Pro、M4 Max 及 M5 上可借此启动到 shell 并使用所有核心，但摄像头、显示控制器和 GPU 等外设仍需继续逆向开发；这不是完整的 M4 Linux 正式支持。

原文链接：https://yuka.dev/blog-2026-10-02-linux-m4.html

论坛讨论链接：https://news.ycombinator.com/item?id=49933869

HN 评论主要从苹果硬件与系统的绑定模式展开，而非验证 WFI 修复细节。一些人赞赏 Apple Silicon 的性能，设想若苹果更开放硬件或销售服务器芯片，Linux 用户和数据中心可能受益。反对者认为苹果的商业模式是出售硬件、系统和服务的完整组合，单卖处理器并非其目标。也有人提到 Mac mini 已被托管用于苹果平台的持续集成，认为服务器产品可能仍能服务现有生态。有关未来服务器芯片或业务方向的说法都只是评论者推测，不能据此写成苹果已经宣布计划。

## 6. Kagi 停止开发 Orion 的 Linux 与 Windows 版，计划开源 (An Update on Orion for Linux and Windows)


Kagi 于 10 月 2 日宣布，停止由公司继续开发 Orion 的 Linux 和 Windows 版本，转而计划公开两端源代码，交由愿意接手的社区推进。它强调 Orion 并未整体停止：macOS 与 iOS 版仍会继续维护，并将得到原先分散在跨平台工作上的开发资源。Kagi 称团队只有少数工程师、完全由用户付费支持，同时坚持不从 Chromium 分叉；把有限人力摊到三个平台难以持续。开源的具体方式和时间尚未确定，公司说将在未来 30 天公布细节，且已联系开源基金会讨论长期托管，但不会担任新项目的核心维护者。Linux、Windows 用户暂时不能把这则公告理解为已有可立即接管的开源发行版；后续进展取决于代码放出及外部维护者加入。

原文链接：https://blog.kagi.com/update-orion-linux-windows

论坛讨论链接：https://news.ycombinator.com/item?id=49941447

HN 的争论围绕 Orion 在不同平台的价值。有人认为 Linux 用户更在意源码开放，闭源浏览器难和 Firefox、Brave 竞争；另一派则从实际使用体验解释为什么仍愿意用它。iOS 用户提到 Orion 能运行 Chrome 和 Firefox 扩展，Firefox iOS 却不支持扩展，这形成实际差别。还有人看重类似 Safari 的续航，以及比 Safari 更合用的界面。另一条支线讨论浏览器耗电表现，有人引用测试说差距不大，也有人称自己的体验相反。评论最终关心：桌面版开源后能否有人维护和测试扩展兼容性。

## 7. 把 tmux 变成桌面系统：按任务组织窗口的构想 (Make Tmux the OS)





这篇文章不是新操作系统发布，而是作者对桌面交互的一份设计提案：把 tmux 的可滚动空间、会话保留和按任务组织，变成普通人能用的桌面。作者指出，笔记本反复插拔外接屏时窗口布局需手动重排，浏览器标签与其他应用分属不同容器，资料又散落在应用私有数据库，传统“打开文件”的工作流难以涵盖这些内容。他设想一个无限画布，由屏幕充当视口，窗口和浏览器标签按任务组合；陌生显示器或投屏默认进入安全展示状态，避免意外泄露私人窗口。局部可借鉴 Niri 的滚动平铺；本地 LLM 只通过受约束接口提出布局方案，由用户预览确认，确定性代码负责执行和保护固定元素。作者承认 Linux VM 上的尝试仍很粗糙，全面演示要继续开发，并列出隐私监控、阅读被误判空闲、布局无淘汰机制等未解问题。

原文链接：https://matduggan.com/what-does-my-dream-os-ui-look-like/

论坛讨论链接：https://news.ycombinator.com/item?id=49937540

HN 评论大多没有把文章当作可立即安装的系统，焦点转向“资料归谁管理”。有人抱怨 Apple 和 Windows 把文件藏在应用或云服务后面，使同一目录在界面与终端里呈现不一致；有人将其归为以文件/数据为中心与以应用/动作为中心的长期冲突。支持传统文件系统的评论认为，中立路径让用户换应用时仍能带走数据；反方提醒，复杂应用格式本身就像小数据库，跨文件关联不容易用目录表示。讨论因此补足了作者方案最棘手的一点：任务视图要跨应用聚合信息，却不能让用户失去对数据位置与控制权的理解。

## 8. C++ Insights：把编译器的隐式动作展开给你看 (C++ Insights – See your source code with the eyes of a Compiler)



C++ Insights 是 Andreas Fertig 的开源工具，基于 Clang 的语法树，把 C++ 源码中的隐式处理展开为仍可阅读的 C++ 形式，让开发者从“编译器眼中”观察代码。项目 README 用继承示例展示编译器补出的特殊成员函数和类型向上转换；还可把 lambda、范围 for、结构化绑定等语法糖展开，显示运算符调用、隐式转换，并推断 auto 与 decltype 对应的类型。作者开发它的初衷是教学：AST dump 太底层，汇编又离原语言太远。工具提供在线页面，也能从源码构建 CLI，并列出 VS Code、Vim、Neovim 等配套插件。README 同时提醒，它依赖 Clang 对 AST 的理解，并不保证所有语言特性都转换得完全正确；这次 HN 分享的是既有项目仓库，而非当天发布的新版本。

原文链接：https://github.com/andreasfertig/cppinsights

论坛讨论链接：https://news.ycombinator.com/item?id=49928361

HN 读者主要把它当作学习 C++ 隐含行为的可视化工具。一位评论者说，自己也想看清“编译器在想什么”；另有人希望 README 用 lambda 捕获作示例，因为捕获外层变量时自动生成的结构与字段比普通 lambda 更能体现价值。回复中有人给出在线样例，指出范围 for 的展开同样能揭示循环变量声明位置等细节。还有人提到自己做过 C++ 到 JavaScript 的转换器，以便逐步显示变量状态；另一位读者希望看到细粒度编译耗时。后两者是延伸需求，不是 C++ Insights 现有功能。

## 9. Kolibri 德语大模型：技术设计、强项与局限 (Aleph Alpha Kolibri: How the sovereign German LLM works)



作者拆解 Aleph Alpha 的 Kolibri 1：这是一款面向德语和英语的开放权重大模型，权重与配置按 Apache 2.0 发布，训练代码及方法并未一并开放。它采用混合专家架构，总计约 781 亿参数，每个词元激活约 34.6 亿；原生上下文 26.2 万词元，并测试到约 104.9 万。作者以德国《基本法》实测其德语分词器，统计得到 35,190 个词元，比 GPT-5 所用分词器少约 15%，有利于在同一窗口处理更长德文。模型还组合局部与全局注意力、德语推理，以及针对缺乏证据时回答“不知道”的训练。按公司评测，它在同等活跃参数级别的德语、数学和企业文档问答表现突出，但作者也列出记忆知识、多轮工具调用、编程代理和超长上下文中段的短板。所谓“主权”主要指欧洲团队与基础设施训练、可在自有设备部署，并不意味着训练材料全来自欧洲；运行权重仍需约 78 GB 显存。

原文链接：https://tej.as/blog/aleph-alpha-kolibri

论坛讨论链接：https://news.ycombinator.com/item?id=49943034

这个 HN 页面上的讨论主要是帖子归类，而非性能复测。版主 dang 表示正把多数评论合并进同日的 Kolibri 官方发布帖，并提醒不要复制评论，以免干扰合并。多位用户认为作者介绍的是朋友团队的模型，并非自己制作的项目，因此不适合标成 Show HN；也有人赞赏文章对模型在证据不足时说“不知道”的 Merlin–Arthur 训练方法的解释。一位自称训练团队成员的评论者强调团队成立时间短、迭代快，并称模型擅长编码和代理任务。这只是参与者观点，不等于独立评测；原文也列出了相关能力的短板。

## 10. 1936 年建成的沃金铁路供电控制室 (Woking Electrical Control Room (2016))





摄影师记录了英国沃金一处南方铁路供电控制室，照片摄于 2016 年。文中称建筑建于 1936 年，是当时管理铁路电力的五座控制室之一；外观只是朴素的混凝土楼，内部却是带白色穹顶的大椭圆厅。中央放着小型操作台，四根铸铁柱托起铜制灯罩，四周黑色面板按地点标示各变电站。作者介绍，值班工程师可在故障出现时调整供电路径并协调维修，当年只需两人在现场负责这一段铁路；不过电话交换机仍须手摇供电。控制室一直使用到 1997 年，随后由另一座变电设施接手大部分任务。文章还说，同批五座中另一座虽仍存在但设备已拆除，沃金这栋建筑已列为英国二级保护建筑，办公区仍在使用，并曾于开放日对公众开放。多张现场照片重点呈现面板、操作台、电话与照明细节。

原文链接：http://www.darbiansphotography.com/woking-electrical-control-room-urbex

论坛讨论链接：https://news.ycombinator.com/item?id=49938399

HN 讨论从照片延伸到控制界面的设计。一名读者称，老式控制室常把线路或设备连接关系直接画在面板上，再把开关和状态灯放到相应位置；他认为很多现代软件仪表盘只展示指标，却缺少系统结构图。另一位从事发电和输电自动化的工程师反驳说，现代工业人机界面仍会显示设施结构，不能把软件看板概括成全部工业控制界面。还有人感叹 1930 年代基础设施也讲究空间美感，并想象今天可能只剩屏幕和普通办公室装修；回应者提醒，这或许有幸存者偏差：后人更愿意传播旧时代漂亮建筑，而忽略当年平庸的房间。
