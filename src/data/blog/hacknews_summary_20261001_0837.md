## 1. Pi 宣布支持 MCP：用沙盒组合工具 (You said no MCP)



Earendil 解释，曾公开声明不支持 MCP 的 Pi，如今把 MCP 纳入核心，原因不只是协议变化：为了让新模型按需加载工具、在对话中调整推理级别，Pi 本就需要补足工具元数据和一个可编排调用的解释器。配置 MCP 后，Codemode 会自动载入，也能单独启用。它在代理循环一侧运行 JavaScript，把多次工具调用、数据处理与模型调用串起来，状态留在会话记录中，而非普通 shell 文件系统。作者仍批评不少 MCP 服务器偏向返回文本、缺少结构化结果，工具之间难以组合；理想形态更接近可智能发现工具的 OpenAPI。文中用 Linear MCP 加 Jev 分类模型分析 167 条开放问题，示范结果为 156 条中性、11 条轻度沮丧、无高度沮丧。这是一次工作流演示和模型判断，并非对整个社区情绪的调查；文章也未宣称 MCP 原有问题已经解决。

原文链接：https://earendil.com/posts/you-said-no-mcp/

论坛讨论链接：https://news.ycombinator.com/item?id=49906637

HN 讨论并未一致赞成必须用 MCP。有开发者举 macOS 应用实例：把 Clop、Crank 等现成能力暴露给代理后，可以用自然语言设定图片转换和备份，省去重写成熟工具的成本。另一位用户说，自己只给 Claude Home Assistant 的 API 密钥，也完成了蓝牙温度计替换和自动化迁移，认为不需要 MCP。回复者强调，密钥留在 MCP 服务器一侧可降低代理泄露凭证的风险；反方则认为若能控制 API 权限，直接在 API 层缩小权限面就足够。争论核心是组合便利与额外协议层是否值得。

## 2. Google 发布 Gemini 4 Argon：先向可信网络防御者开放 (Gemini 4 Argon)




Google 9 月 30 日宣布 Gemini 4 Argon，定位于长流程软件工程、法律和金融等专业知识工作以及网络防御，但目前只通过 Fairwind 计划向一批可信防御者逐步开放，开发者、企业和普通用户尚需等待后续扩围。官方称单次输出上限从此前的 6.4 万 token 提升至 100 万 token；这说的是输出容量，不能误写成上下文窗口。Google 报告其在长流程编程评测 DeepSWE v1.1 得分 77.9%，长视频理解 LVBench 得分 91.7%，这些是发布方披露的指标，不等于所有实际场景的保证。公司还称模型能发现、验证和修补漏洞，并将对选定防御团队开放不带网络安全护栏的版本，同时继续测试滥用防范、提示注入和失控监测。未来计划先覆盖付费 API 客户及 Google AI Ultra 订阅者；原文没有给出这些用户的确定开放日期。

原文链接：https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/

论坛讨论链接：https://news.ycombinator.com/item?id=49913571

HN 置顶讨论更多是对现有 Gemini 3.8 Flash 与使用入口的体验，并非 Argon 实测。有用户称 Flash 配合 Antigravity 帮他修复 Strix Halo 上的 ROCm/llama.cpp 问题，并贴出代码。另一支讨论批评 Ultra 用户被推向 Google 自家工作台，觉得缺少选择；回复指出仍可通过 API 接入其他代理框架，也有人提到 Pi 插件。上述均是个人经验或入口争论，不能据此推断尚未广泛开放的 Argon 已通过用户验证。

## 3. 佛蒙特州把 5500 多户电池聚成虚拟电厂，削峰并撑过停电 (Vermont replacing power plants with home batteries)





BBC 报道，佛蒙特州公用事业公司 Green Mountain Power 把 5500 多户家庭电池与其他资源联网，形成约 110 兆瓦的虚拟电厂，用于高峰时减轻电网负担，也让住户在暴风雨停电时保留备用电力。报道中的租赁方案为每户装两块电池，月费 55 美元、租期十年；住户参加调度时仍保留一定电量。约一半装电池的家庭也有太阳能板，但电池本身不发电，关键在于把低谷时存下的电移到高峰使用。GMP 称这套方案去年为客户节省约 1100 万美元，部分燃油或燃气尖峰机组已随退役被替代；仍有四座机组偶尔运行，所以不能说传统电厂已全部消失。公司希望到 2030 年消除停电，并扩大储能覆盖，但接入成本、批发市场规则及公用事业投资激励仍是推广障碍。

原文链接：https://www.bbc.com/future/article/20260928-a-virtual-power-plant-hidden-in-vermont-homes-is-keeping-the-lights-on-during-storms

论坛讨论链接：https://news.ycombinator.com/item?id=49897993

HN 的一位北卡罗来纳州参与者描述本地方案：每块电池每月约获 50 美元，电力公司一年最多调度 36 次，常在夏季傍晚或冬季清晨的用电高峰，让家庭暂时靠电池供电，偶尔还向电网回送电。他觉得补贴改善了经济性，但也提到冬季可能需要先从电网充电。有人追问，若电池被调空时遇到本地停电怎么办；另一名同项目用户说可设最低保留电量，自己设为 20%，并可有限次数拒绝调度。还有评论建议把日常荷电量维持在 50% 至 80%，这是建议而非 GMP 的既定规则。

## 4. Show HN：展示 52.6 万颗小行星，并叠加在轨卫星 (Show HN: Real-time Solar System with 526k asteroids and all tracked satellites)


这个 Show HN 项目的网页主要是俄语交互界面，几乎没有说明文章；以下功能与数据来源按作者在 HN 的自述归纳。作者称它在浏览器中按真实比例展示太阳系当前状态，并叠加 CelesTrak 目录中的地球周边天体；卫星轨道由 TLE 数据经 SGP4 推算，小行星和彗星来自 JPL 的小天体数据库，航天器位置取自 JPL Horizons，数据每天刷新。页面用 WebGL2 绘制，把轨道计算放在 Web Worker 中，约 30 MB 的小行星数据在后台加载。用户可以拖动旋转、滚轮缩放、点选天体查看卡片和轨道，也能用时间滑杆前进或回退，并按发射日期显示或隐藏卫星。标题中的 52.6 万来自 HN 项目介绍，不能据此推断所有未知小行星或卫星都已收录；这首先是交互可视化，而非预警系统。

原文链接：https://space.bl2.net/

论坛讨论链接：https://news.ycombinator.com/item?id=49898778

HN 评论集中在数据精度和用途。曾为 NASA 望远镜计算小行星位置的用户询问航天器轨迹来源，作者回答每天从 Horizons API 获取各航天器的状态向量。另有人追问回到过去是否使用历史 TLE；作者承认是把当前 TLE 向后推算，超过 90 天会标为估算，因此历史画面不应当成实测轨道。还有用户指出某颗小行星未出现，提醒目录并非无遗漏。有人问这能否说明地球已有充分的小行星撞击预警；回复提到 NEO Surveyor、DART 和 Rubin 巡天等独立项目，但并未声称这个工具具备预警能力。

## 5. NASA 被曝邀旧工程师评估 SR-71A 复飞 (NASA asked several former SR-71A staffers to help secret restart)





《航空周刊》采访两名前 SR-71A 测试工程师后报道，NASA 曾在今年夏季邀请旧项目人员参与 844 号机的复飞尝试。该机自 1999 年最后一次飞行后长期露天展示；报道依据卫星图像和受访者说法，称它今年春季已从展台移入机库检查，现场有人作业。受邀的 Mike Relja 和 Tim Conners 均未接受工作。Relja 指出，机体、发动机近 27 年未飞行或按旧标准维护，专用燃料、备件、地面设备和熟练人员均需恢复，成本与可行性问题很大；Conners 认为旧手册及其他退役机体的部件或可提供帮助。NASA 发言人没有证实复飞项目，也没有说明移机目的。局长公开谈及重建 X 型试验机队，但不能据此断言 844 号机已获复飞批准，更不能写成即将升空。

原文链接：https://aviationweek.com/defense/aircraft-propulsion/nasa-asked-several-former-sr-71a-staffers-help-secret-restart

论坛讨论链接：https://news.ycombinator.com/item?id=49890733

HN 评论把技术价值与现实代价分开讨论。有评论者认为，即使最终不飞，让工程团队重新掌握高速、高空载人研究机的制造和维护知识，也有保留濒失能力的价值。另一位自称资深 SR-71 爱好者、曾参与军机工作的评论者则质疑：若传闻属实，重启老机可能出于怀旧；现代无人平台或更省成本，也能把重量留给燃油与传感器。回复进一步追问是否能换装现代发动机，以及发动机与机上电气系统是否高度耦合。这些是网友对方案的讨论，并非 NASA 已公布的技术计划。

## 6. 用矩阵解《异星工厂》的品质升级 (Solving Factorio Quality)





《异星工厂：太空时代》把物品分为普通至传奇五档；品质模组让制造或回收时有概率升级，而回收机通常只返还约四分之一原料。作者把各档物品的分布写成向量，把制造、筛选、回收写成转移矩阵，再用稳态流量方程求解循环生产，避免逐次模拟随机结果。文章依次分析只靠制造碰运气、物品自身反复回收、制造与回收形成闭环，以及太空中小行星再处理四类策略。在示例设定下，投入普通原料的建筑机器人升级线，最高品质模组和零生产力加成时，每分钟约消耗309套原料、产出2个传奇机器人；另一种已达300%生产力上限的设定，理论上可把普通成品转成传奇而不损失原料，但要付出大量机器与模组的成本。作者最后把计算器由 Rust 改写为 TypeScript，开放网页工具与代码，供玩家调整参数。

原文链接：https://exyr.org/2026/solving-factorio-quality/

论坛讨论链接：https://news.ycombinator.com/item?id=49887343

HN 讨论把数学模型带回实际建厂。DanielHB 分享用一台组装机切换配方、从基础资源制造多种传奇物品的蓝图，但指出换配方会清空生产力进度，而且占地、流体配方都限制实用性。另一位做过 Python 求解器和网页工具的玩家赞同矩阵建模，同时补充：若目标只看每单位普通原料换多少传奇成品，加速模组不划算；若瓶颈是昂贵的传奇机器，低品质阶段加入少量加速模组，可能以多耗廉价原料换取更高吞吐量。评论因此强调，所谓“最优”取决于原料还是设备才是约束。

## 7. 从词袋到 Jev：文本分类为什么又受关注 (Language models for text classification: From bag-of-words to Jev)





机器学习研究者 Sebastian Raschka 以文本分类史解读 Jev：词袋配朴素贝叶斯或逻辑回归便宜、适合作基线，却丢失词序；RNN、CNN 和 BERT 等模型逐步改进上下文处理，大型生成模型则能直接按提示分类，但成本更高。Jev 提供 Choice、Noul、Score 三种决策接口，分别处理互斥类别、独立的是非概率与等级评分。作者在 IMDb 的2.5万条测试评论上测得 Choice 准确率96.47%、运行约22分钟、花费约0.65美元，认为其优势是无需为每类任务单独微调，同时兼顾速度和价格；但测试集是否进入训练数据未知。Jev 的架构、训练数据与所谓 RLCD 方法未公开，文中关于类似 ModernBERT 和校准奖励的讨论明确属于推测，并非已证实的内部实现。

原文链接：https://magazine.sebastianraschka.com/p/classifier-history-and-jev

论坛讨论链接：https://news.ycombinator.com/item?id=49891203

HN 评论既认可这篇文章的技术脉络，也提醒别把演示当成万能智能。Topfi 说，一边有人把 Jev 吹成通往 AGI 或“不会幻觉”的突破，另一边有人只因它是分类器就否定价值；一些游戏演示实际输入的是游戏状态，而非即时视觉画面。aesthesia 补充词袋到神经网络之间还可讲连续词袋与 fastText 式的词向量平均。nzoschke 则说其团队正在比较邮件分类方案，Jev 看起来有应用潜力。讨论焦点是通用性、延迟与成本的权衡，而不是宣称分类技术被重新发明。

## 8. 油价暴涨，多付的钱最终流向哪里？ (When oil prices spike, where does the money go?)





两位佐治亚理工学院经济学者在4月发表的分析中，以美国原油价格从2026年2月底每桶66美元升至4月13日101美元为例，解释供应受阻时消费者与企业为何迅速承受涨价。额外支出的大头沿产业链流向产油企业，但最终受益者取决于所有权和税制：沙特石油收入主要进入政府财政；美国西得州油企短期成本涨幅低于售价，收益可能用于股息、回购、还债或再投资；英国北海油田由私人股东与征收额外利润税的政府分得；挪威则把油气收入纳入主权财富基金。文章也指出中东产区同时面临保险、安保和运输成本上升，不能把油价涨幅全当净利润。作者对俄罗斯油收流向寡头与军工体系的判断带有推测性，强调短期消费者难避价格冲击，长期降低对化石燃料依赖才可能减轻暴露。

原文链接：https://theconversation.com/when-oil-prices-spike-where-does-the-money-go-280763

论坛讨论链接：https://news.ycombinator.com/item?id=49888182

HN 可见讨论主要围绕“谁算产油利润的受益人”。ggm 以澳大利亚退休金为例说，养老金基金持有油企、保险或建设公司资产时，普通储户也可能间接分享价格上涨及后续修复工程的收益；他认为不宜把资本收益只想成少数西装高管拿走，也承认自己因投资而间接卷入化石燃料风险。这是该网友的个人立场，不代表所有储户都同等受益。回复者 fooker 纠正其把基金资产总额与一国年度 GDP 直接比较，指出这是存量与流量的不同口径。

## 9. Backblaze 发布 2026 年第二季度硬盘故障统计 (Backblaze drive stats for Q2 2026)




Backblaze 公布 2026 年第二季度硬盘统计：监测的 359,101 块硬盘中，扣除启动盘及未达纳入标准的型号后，354,415 块进入季度分析，累计出现 1,498 次故障，年化故障率为 1.73%；截至 6 月底，纳入长期统计的硬盘年化故障率为 1.41%。不同型号差异很大：三款季度年化故障率超过 6.95%，其中一部分盘龄较高，另有型号样本量较小，不能把单季数字当成整家厂商的品质排名。20TB 以上硬盘已占该季度样本逾四分之一。文章还解释 CMR 与叠瓦式 SMR 的取舍：SMR 可在相近盘片上增加约 10% 至 25% 容量，却可能增加随机改写和数据重建的负担；HAMR 是另一种提高密度的技术，两者并不互斥。Backblaze 强调当前统计表中没有 SMR 硬盘，未来若引入，会单独标明并观察其故障率。

原文链接：https://www.backblaze.com/blog/backblaze-drive-stats-for-q2-2026/

论坛讨论链接：https://news.ycombinator.com/item?id=49893002

HN 讨论主要围绕硬盘是否真的越来越耐用。一位评论者回顾 Backblaze 历年统计，认为硬盘寿命明显拉长；所举不同年份的故障率和盘龄是其个人归纳，不宜直接当作本季报告结论。有人追问，改善来自盘体制造，还是散热、供电、控制器及运维变化；另有人猜测，消费市场转向 SSD 后，HDD 产品结构也改变。评论中还提及早年洪水后的采购影响旧数据，并引用 Backblaze 旧分析质疑传统“浴缸曲线”。这些均是讨论中的解释或假设，本篇季度数据不能单独证明因果。

## 10. 一位波兰作者眼中的 2026 年九月：全球冲击如何叠加 (September 2026: The world today, as seen by one Polish guy)



波兰作者 Tom Wojcik 以个人视角把九月的能源、粮食、利率、安全与气候议题串在一起。他认为，过去数十年各国和家庭为追求效率，逐渐用跨境供应、廉价融资及外部安全保障替代库存和冗余；当霍尔木兹海峡运输受阻，燃油、化肥和液化天然气价格的影响便沿供应链传到欧洲，也让波兰的取暖和粮食成本更脆弱。文章随后讨论日本利率上升、国际借贷成本变化，以及波兰国防支出、河流水位降低、电力冷却用水、青年就业和人口老化等压力。作者的主线不是宣布世界末日，而是认为多种冲击同时到来时，缺少缓冲的系统更难承受。他也引述欧盟关于当年冬季没有即时供能担忧的说法，主张家庭准备饮水、照明、现金及停电应对等有限的缓冲。文中数字涉及快速变化的时局，部分出自单一媒体，应按作者截至 9 月 26 日的资料与判断来读，而非确定预测。
